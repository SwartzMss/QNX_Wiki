QNX SDP 8.0.6 Release Notes

QNX SDP is a cross-compiling and debugging environment, including an IDE and command-line tools, for building binary images and programs for target boards running the QNX OS 8.0.6. These release notes describe the key features of this new release and the notable improvements since the previous release, and provide installation instructions.


Date of this edition: November 12, 2026

Target hardware

This product can run on x86-64 hardware platforms and AArch64 platforms that support the ARM 64-bit (A64) Instruction Set.

Development Host Operating Systems (OSs)

You must install QNX SDP 8.0.6 onto a development host with one of the following 64-bit operating systems:

  • Microsoft Windows 11
  • Ubuntu Desktop 24.04 LTS, Ubuntu Desktop 22.04 LTS, or Red Hat Enterprise Linux 9
Note:
QNX SDP isn't supported on host systems that use ARM processors or macOS.

What's new in QNX SDP?

Component Feature Details
Kernel In-kernel Pipes Creation Control. In-kernel pipe creation can now be restricted via the PROCMGR_AID_KPIPE_CREATE ability.
Kernel CPU On/Offlining Events. The procmgr events can now notify user programs of CPUs being offlined or onlined.
Kernel Generic Interrupt Controller (GIC) Kernel Module Multiple Redistributor Support. The GIC version 3 kernel module now supports systems with multiple contiguous redistributor regions.
Kernel Kernel Event Tracing Kernel Version Capture. Kernel event traces now log the version of the kernel they were captured on.
Kernel SIGEV_PULSE Inherited Priority Configuration Support. The SchedSet() kernel call can now be used to set the priority of SIGEV_PULSE events created with SIGEV_PULSE_PRIO_INHERIT.
Kernel Kernel Event Tracing CPU Offlining Support. Kernel event tracing now supports tracing while CPUs are being offlined/onlined.
Kernel Runtime Linker RTLD_NOLOAD Support. The dlopen() function now supports the RTLD_NOLOAD flag.
Kernel Straight-line Speculation Hardening. The kernel now mitigates straight-line speculation following the ERET instructions on AArch64 systems.
Networking Driver updates. The devs-cgem.so and devs-clk-xilinx.so drivers are updated to support the AMD Versal2 VEK385.
Networking Precision Time Protocol (PTP) Ethernet packet timestamping. The ioctl() entry now includes a new command, PTP_ADD_OFFSET, which allows adding a time offset to the current time.
Networking FreeBSD version update. The FreeBSD version that QNX OS networking is based on has been updated to 14.4-RELEASE-p9.
Networking Packet filtering (PF). The version of pf provided with QNX SDP now supports Ethernet filtering.
Networking Network File System (NFS). The etc/exports file that defines remote mountpoints for NFS, now has an -all=uid option. This option allows you to map all client users and groups to a specified UID.
Networking Unbound version update. The Unbound DNS resolver has been updated to version 1.25.1.
Networking Updated io-sockmodule compatibility version. The current io-sock driver and module API version has been updated to reflect changes to Virtual Network (VNET) and Dynamic Per-CPU (DPCPU) support across modules. The minimum supported version is unchanged because most existing drivers and modules remain compatible. Modules that use VNET or DPCPU variables and were built with an older SDP might need to be rebuilt.
Filesystems Allowing mounts with more than 47 devb processes.

Block device driver devb processes now offer an alternative method of receiving mount requests. This new method bypasses a system limit for the maximum number of concurrent mount-handling resource managers.

To enable this method, set the BROADCAST_MOUNT_LISTENER=NO variable in the devb process environment.
Note:
This functionality relies on a new version of libc (8.0.6). Specifying this environment variable with an older version of libc may prevent the devb process from receiving any mount requests.
Filesystems New Device Command to reset the io-blk disk cache state.

A new DCMD_FSYS_PGCACHE_CTL_OP_PAGESORT sub-command has been added to the DCMD_FSYS_PGCACHE_CTL command.

This command can be sent to a file descriptor opened against the disk device (E.g., /dev/hd0), helping substantially regain the lost sequential performance.

Note:
Some disk access patterns may result in gradual loss of file sequential read or write performance.
Filesystems Access permissions update for mkqnx6fs. The -R command-line option of the mkqnx6fs utility now needs access permission, unlike before.
Security OpenSSL update. QNX OS ships with OpenSSL version 3.5 as well as version 3.0 (3.0 is the default).
Command Line Tools Rust repackaging.

A new Rust package containing the Ferrocene SDK from Ferrous Systems for QNX SDP 8.0.6 has been made available with this release.

The Ferrocene SDK is available as a separate optional downloadable package with QNX SDP 8.0.6 for convenience for our customers and should not be considered part of the QNX roadmap supported products. Packaging and availability may change in future releases.

For more details on the Ferrocene SDK version 26.08, refer to the Ferrous QNX8 Manual and the Ferrous Ferrocene 26.08 — Ferrocene Release Notes.
Command Line Tools Bootstrap Configuration Files. The bootstrap programs' developers now have an option to have mkifs patch for their binary's parameters, based on a textual configuration next to the binary's file attributes. This is an alternative to parametrization via the command line, and this allows for more clarity and potential build-time detection of configuration errors.
Command Line Tools Bootloader. The developers who build their own QNX6 filesystem image are now able to override the second-stage bootloader program via a new booter attribute in the mkqnx6fsimg utility.
Graphics and Screen Image codecs. The following libraries have been updated:
  • libtiff is now version 4.7.2
  • libgif is now version 6.1.3
  • libfreetype is now version 2.4.3
BSP and Drivers Support for the following Generic Interrupt Controllers (GICs):
  • GIC Distributor (GICD)
  • GIC Redistributor (GICR)
  • Interrupt Translation Service (ITS)
 The Startup library now supports retrieving GICD, GICR, and ITS base addresses from the Flattened Device Tree (FDT). The BSPs don't need to hard-code GIC base addresses. This feature also supports GIC version 3 configurations which include one or more ITS nodes.

Installing QNX SDP

To use QNX SDP 8.0.6, you need to have QNX Software Center 2.0.4 or later. For information about installing and opening this other product, refer to the Install and launch the QNX Software Center chapter in the QNX Software Center User's Guide.

Note:

You install QNX SDP 8.0.6 as a new baseline product by installing QNX SDP 8.0.6 with the conservative installation policy selected. Currently, you cannot update an existing QNX SDP 8.0.x installation to QNX SDP 8.0.6 using a patch set.

To install the QNX SDP 8.0.6 product:

  1. Open the QNX Software Center and click Add Installation.
  2. In the New Installation Wizard, expand QNX Software Development Platform 8.0, select QNX Software Development Platform 8.0, and then click Next as needed to navigate to the Installation Properties page.
  3. In the Installation Properties page, for Update Policy, select Conservative, and then complete the rest of the installation steps.

For more information, go to the Install the QNX Software Development Platform chapter in the QNX Software Center User's Guide.

To access the contents of the package, right-click QNX OS and QNX Tool Suite, choose Properties, then click Package Contents. Some of the packages may contain no files but instead references to contained packages (or subpackages), in which case the contents page display a note saying so. To access the list of subpackages, right-click the package, choose Properties, then click Package Dependencies. Because the baseline OS product has many inter-package dependencies, sometimes you have to go through multiple levels of subpackages to access the included files.

Note:
For more information related to QNX SDP 8.0.6 updates, refer to the QNX SDP 8.0.6 Product Updates Release Notes prior to installing those updates.
Note:
Some packages in this release include experimental files. The maturity level of individual files is displayed in the Status column in the package contents table. The individual files in a package can have different maturity levels.

You can also obtain the maturity statuses of files by generating a manifest report. For more information, refer to the Manifest Reports & File Lookup chapter of the QNX Software Center User's Guide.

Each package has its maturity level. You can learn this by right-clicking the package, choosing Properties, then clicking General Information. In the Legal and Regulatory Information panel, there's a Status field. For details about the possible values of this field, refer to Package status in the Deploy licenses to users section in the QNX Software Center User's Guide.

Warning:
QNX users must deploy the complete QNX 8.0.6 patch set, as several features introduced in version 8.0.6 rely on tightly coupled OS dependencies. Partial adoption of the patch set may result in incompatibilities or unsupported configurations. Full patch integration is required to ensure proper functionality and system stability.

Debug information for shipped binaries

The QNX SDP target binaries are generated with debug information (-g), with the debug form of the binary stored in a separate binaryName.sym file. The non-sym form is stripped of the debug and .ident information (use -s works only on files containing the .ident section).

Most target packages include debug information (.sym files). The binaries and their .sym files are linked, so gdb understands where to find the symbol data. There's no need to store .sym files for the binaries on a target.

If the debug symbols are especially large, there might be a separate debug package in the QNX Software Center. To install debug symbols in this case, select your installation from the toolbar, then go to the Advanced tab. Click Edit Installation Properties. In the property dialog that opens, ensure that the Install debug symbols checkbox is selected (this box is selected by default). Click OK.

If you decide to not install the debug information but later want it, you can right-click a package and choose Install debug symbols.
